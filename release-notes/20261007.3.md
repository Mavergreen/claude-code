Second release. Mavergreen's `avxemu` (which lets Claude Code run on CPUs without AVX2) is now linked into the patched binary instead of being injected with `DYLD_INSERT_LIBRARIES`, and each of Claude's Bash commands gets a few guards for 10.9's older tools.

What changes for you:

- **avxemu is linked, not injected.** Release 1 injected avxemu through `DYLD_INSERT_LIBRARIES`, and only on Macs without AVX2. The patch now adds `/usr/local/mavergreen/avxemu/lib/libavxemu.dylib` as a load command on every Mac, where it does nothing on CPUs that have the instructions, so `claude` needs no `DYLD_*` variables and the programs Claude runs no longer inherit avxemu through `DYLD_INSERT_LIBRARIES`. Checked on Claude Code 2.1.292: `--version` prints `2.1.292 (Claude Code)`, `mcp list` exits 0 and `-p hi` answers "Not logged in".
- **Updating re-patches once.** Each new Claude Code version is patched on its first launch, which takes a second or two. After that it starts as before.
- **Shell guards for Claude's Bash tool.** Before each command, a `shell-bin` directory goes first on `PATH` with a `mktemp` that works without a template (as on current macOS), a `timeout`, and an `env` that understands `-u` and `--unset`. A `cd` or `pushd` with no target, or an empty one, aborts the command instead of going home; `cd ~` still works. Inside Claude's Bash commands, your own `cd` and `pushd` aliases and functions (rvm, nvm, autoenv) are replaced by this guard. Your own `CLAUDE_ENV_FILE` still runs, after ours.
- **zsh acts like bash in Claude's commands.** Under zsh, Claude's commands split unquoted variables and pass unmatched patterns through as bash does, so commands written the bash way work. Your own Terminal is unchanged, and your own `CLAUDE_ENV_FILE` can turn either option back off.
- **GNU tools of the same names.** Inside Claude's Bash commands the guards' own `mktemp`, `timeout` and `env` come first on `PATH`, so GNU versions you installed under those names (for example MacPorts' gnubin) are not used there.
- **rg in Terminal.** Mavericks Forever put an `rg` in `/usr/local/bin` only so Claude's Grep tool could work with its built-in `rg` switched off. Claude's Grep tool has used its built-in `rg` since release 1, and when no `rg` is installed, Claude's Bash commands get that built-in one too. If you used that `rg` in Terminal, install ripgrep yourself, for example from pkgsrc or MacPorts.
- **kevent64.** The fix for the launch crashes already shipped in recaulk `20261006.1`; nothing more is needed here.

Search check. Claude Code's binary also contains its own `rg`, `ugrep` and `bfs`. We only switch a built-in tool on when it runs within twice the time of the standalone tool, on both a small tree and `/usr/share`. All three are correct: `rg` gave 60 of 60 clean runs identical to an external `rg` over `/usr/share`, `ugrep` had no count differences over 352 files, and `bfs` matched `find` on 916 and 22,158 files. Each built-in pays about 0.09 seconds to start, though (about 65 ms image load and 25 ms for avxemu):

- Small-tree warm medians: `rg` 0.107 s against 0.019 s, `ugrep` 0.097 s against 0.014 s, `bfs` 0.095 s against 0.009 s.
- On `/usr/share`: `rg` 1.50x, `ugrep` 1.47x, `bfs` 4.19x the external tool's time.

On the small tree all three built-ins took about 6 to 11 times the standalone tool's time, so `ugrep` and `bfs` stay unused and Claude's Bash commands keep using 10.9's own `grep` and `find`. `rg` is unaffected: Claude's Grep tool has used the built-in `rg` since release 1, and still does.

Checked on the same pristine 2.1.292 binary, this release's patch against release 1's:

- **Load commands.** The new `libavxemu.dylib` is ordinal 1, so the existing ordinals 1-4 become 2-5 and the bind streams are renumbered to match.
- **Header and image base.** The header pad grows by 4096 bytes and the image base moves from `0x100000000` to `0xfffff000`: `__TEXT` is one page larger and starts one page lower. Every other segment keeps its address, and file offsets move by 4096.
- **Code and data.** 463 of 241,362,112 bytes differ, all base-relative values that drydock re-bases: 448 in `__TEXT,__unwind_info`, 8 in `__TEXT,__init_offsets` (offsets +0x1000) and 7 in `__TEXT,__text` (the 7 references to the header drydock reports repairing). drydock verifies the result before writing it.
- **Tables.** Rebase, bind and export table sizes are unchanged.

In practice: apart from the avxemu link and the larger header, the patched program is the same as release 1's.
