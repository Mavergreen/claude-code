Third release. New Claude Code versions are patched when a session ends rather than when the next one starts, Claude Code can save its login in 10.9's Keychain, and Claude's Bash commands get GNU-compatible versions of the tools it most often got wrong on 10.9. It is also the first release whose installer and launcher were tested end to end on a 10.9.5 guest with AVX2 hidden, before publishing.

What changes for you:

- **Faster first launch after an update.** Claude Code's updater downloads a new version during a session, and the first launch after that used to spend a few seconds verifying and patching it. Now, when a session ends, a background job patches the version your next launch will run. The launcher still patches anything this misses, such as after a session was killed.
- **Your login is saved in the Keychain.** Claude Code saves its credentials with a `security` option 10.9 lacks, and 10.9 reported success anyway, so `/doctor` called the Keychain unwritable and a console login could not save its API key. A small `security` wrapper now translates the option for 10.9, without ever putting the secret on a command line, and reports failures the way current macOS does.
- **GNU options in Claude's Bash commands.** A scan of our own Claude sessions on 10.9 found the commands Claude most often ran that 10.9's tools refuse or get wrong. Inside Claude's Bash commands, these now behave as on GNU systems: `cat -A`, `head -n 0` and negative counts, `sort -V` and `-h` (matched against GNU coreutils 9.11), `readlink -f`, `realpath`, `sed -i FILE`, `-r` and `N,+M`, `tac`, `uniq -w`, `date -r FILE`, `paste` reading stdin, `xargs -r`, and `base64 -d`. On 10.9, `base64 -d` means "debug" and silently re-encodes instead of decoding. Any command 10.9's own tool already accepts runs it unchanged, at a cost of about 2 ms. Your own Terminal is unaffected.
- **`claude install stable`, `rc` or a version sticks.** Choosing a channel or a version with `claude install` sometimes ran it only once, and the next launch went back to a newer download. It now stays until that channel's updater fetches something newer. The `rc` channel (`/config`'s "slow") is treated like stable.
- **A version Anthropic does not publish runs the latest.** Asking for a version the download server does not have used to report that it "could not verify" the version "while offline". The launcher now says the version is not published and runs the latest instead.
- **`claude install` of a version before 2.1.207 is refused** with a reason, instead of downloading a version the launcher would never run.
- **No more `~/.local/bin` PATH warning from `claude update`** when your home folder is reached through a symlink.
- **Installing without a password prompt.** If your `sudo` needs no password, `install.sh` no longer asks for one, so it also works with no terminal attached.
- **Moving from Mavericks Forever: quit every running `claude` first.** Installing removes Mavericks Forever's `claude` and `rg`, so a session still running from it loses its Grep tool. `install.sh` now says so before it installs, as the README does.
- Smaller fixes: `env -u` takes any name GNU `env` does; `timeout` always stops a command when the time runs out, however short the limit; the `pushd` guard says where `pushd` would really have gone; and a dozen fixes to the launcher's fallbacks, the Mavericks Forever takeover and packaging edge cases.

Checked before release, on a Mac OS X 10.9.5 guest (Mavergreen/mavericks-vm) whose CPU reports AVX but not AVX2, so the patched Claude Code ran through avxemu: `install.sh` installed every package, and the end-to-end test passed all seven of its checks. They cover a fresh bootstrap, a second launch that patches nothing new, `claude update`, a held version, `claude -p`, the computer-use server connecting, and Claude Code idling instead of spinning with wide characters on screen.
